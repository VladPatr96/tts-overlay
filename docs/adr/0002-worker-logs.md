# 0002. Логи воркеров живут вне `tts-overlay.log`

Статус: принято (2026-10-20, фиксирует сложившееся).

## Контекст

Воркеры (`edge-worker.py`, `stt-worker.py`) — отдельные процессы Python. Оверлей читает их stdout как канал ответов, поэтому диагностику туда писать нельзя. Писать в `tts-overlay.log` из двух процессов сразу — значит гонка за файл и перемешанные строки.

## Решение

Каждый воркер пишет свой журнал сам:

| Воркер | Журнал |
|---|---|
| Edge | `%TEMP%\edge-worker.log` |
| Распознавание | `stt/stt-worker.log` (в `.gitignore` по маске `*.log`) |
| Silero | журнала нет; ошибка уходит ответом `ERR …` и пустым `.pcm` |

В `tts-overlay.log` оверлей пишет только то, что видит сам: ответ воркера, таймаут, переход на запасной движок.

## Последствия

- Разбирая сбой воркера, смотри два журнала: `tts-overlay.log` (что увидел оверлей) и журнал воркера (почему).
- Путь журнала Edge зависит от `%TEMP%`, а не от папки проекта — это отступление от правила про относительные пути, оставлено намеренно: папка проекта может быть только для чтения.
